minor: runLoad's recover defer re-panics after finish, so a Loader panic kills the process while Close is still inside joining.Wait. The recover is documented as the way f.done closes and Close is not stuck, but the re-panic runs before joining.Done, and the panic is on the loader goroutine, not the Get stack. An unrecovered panic on that goroutine crashes the process. Close never returns, waiters never observe ErrClosed, and a test cleanup that calls Close during an in-flight load cannot finish. Spec rule 8 requires Close to wait for the Loader call to return and to wake every current waiter with ErrClosed. The plan says the spec does not require surviving a Loader panic and that hidden tests are unlikely to panic the Loader; that leaves the only failure mode that still deadlocks Close as a process crash. Finish, close f.done, joining.Done, and return. Do not re-panic on the loader goroutine. Surface the failure as the published errLoaderFailed the waiters already receive when the cache is still open.
minor: finish deletes inflight before the closed check and the admit. A later edit that returns between those steps, or that splits the critical section the prose says must stay one hold, leaves a successful key in neither map. The next Get misses, starts a second Loader, and can admit a second copy while the first finish is still deciding. Rule 2 is then two loads for one key. Delete only after the admit-or-discard decision, in the same hold as close(f.done), or set a published bit before the delete so a racing Get still joins this flight.
nit: Get registers waiters.Add before the hit path returns, so Close's waiters.Wait includes Gets that never waited on a load. That matches the plan's "every Get that observed !closed" reading and is not a rule 8 failure, because those Gets return and Done. It couples hit latency to Close. A comment that this is intentional, and that moving Add to the miss path would let Close return while a hit is still inside Get, would stop a later edit from "fixing" it into a post-close success return.
nit: snapshot's closed check precedes the f.done receive, so a flight that finished and was admitted before Close set closed is returned to a waiter as ErrClosed. Rule 7(a) and rule 8 require that. The private list does not lock it. Add a synctest case: load succeeds and finish returns, then Close sets closed, then a joiner that has not yet snapshotted must get ErrClosed, not the bytes. Without that test a later reorder of the two reads inside the hold ships and the public suite still passes.
