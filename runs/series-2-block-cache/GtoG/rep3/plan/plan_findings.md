The rebuttal of the AfterFunc clause is correct: a production Get cannot register AfterFunc on a caller ctx and still park durably for both bubbled and ordinary contexts, and the pre-check plus decide order matches rule 7 at decision time. Close's unlock-then-cancel-then-close(done)-then-Wait order no longer holds mu across a wake that must precede loads.Wait.
minor: publish's closed branch is unreachable and will drift from the real discard path. Get refuses new flights after closed is set, and Close moves every pending flight to flightDiscard before it unlocks, so runLoad's publish always returns at `state != flightPending` if the cache has closed. The `if closed` arm never runs, yet it is the only place the plan says a late loader result is discarded. A later editor who treats that arm as the close-window handler, or who publishes before checking state, will double-close done or store a result rule 8 says to drop. Delete the arm, or replace it with a comment that Close is the only writer of flightDiscard and publish must no-op.
minor: rule 7(b) is only the pre-check, so a Get that has already parked cannot return until the Loader returns. Spec priority (b) is "ctx.Err() if its own ctx is Done while the load is still in flight." After `<-f.done` the flight is terminal, so decide never applies (b) to a cancel that arrives during the park; that waiter waits out a slow or wedged Loader and then receives (a) or (c). The public suite does not cancel a parked waiter, and the plan's extra tests only cancel before the park or accept the post-resolve result, so this will not fail the shipped suite. It is still the production contract: a caller deadline does not bound a waiting Get. State that limit next to rule 7 in the plan so a later editor does not "fix" it by putting ctx.Done() back in the select.
nit: clone(nil) returns a non-nil empty slice, and the plan stores that as a successful block. The spec only requires a fresh copy and that an error path discard bytes; it does not define a nil success. The public suite never loads nil. Keep the distinction (error returns a nil slice; a nil success is a cached empty block) in the clone comment, or a later edit that returns the Loader's nil slice will make a hit and an error indistinguishable to callers that check the slice and not the error.
nit: the second Close waits on the same WaitGroup with no closing flag of its own. That is correct only while every Add stays before the closed check's unlock and Done stays deferred in runLoad. A later Add after Wait has observed zero panics. The plan states the constraint; keep Add and the closed store in the same critical section and do not split them when the file is edited.
