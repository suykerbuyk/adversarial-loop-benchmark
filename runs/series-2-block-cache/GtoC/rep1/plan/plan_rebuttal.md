# Plan rebuttal

Each finding in `plan/plan_findings.md` is fixed. The revised `plan/plan.md` is the only source of truth. Previous rebuttal item 3 (`sync.Once` as the only join) is withdrawn.

1. **major: extra test 16 hangs because `sync.Once.Do` is not durably blocked under `synctest`, and the one join rule 8 must observe cannot be observed that way.** Fixed. `closeOnce` is gone. Close uses a mutex-guarded join channel `joined`. Under `mu`, the first Close sees `joined == nil`, creates the channel, sets `closed`, clears the maps, and unlocks. It then calls `loadCancel`, `wg.Wait`, and `close(joined)`, in that order. A later Close sees `joined != nil`, unlocks, and receives on the channel. The receive is outside `mu`: holding `mu` across it would deadlock with `publish`, which must take `mu` before `wg.Done` so `Wait` can finish and close the channel. A channel receive is durably blocked, so test 16's second `synctest.Wait` returns. The channel is closed once, by the Close that created it, after `Wait`, so a second Close cannot return while a committed Loader is still running, and there is no double-close. Data model, Close section, invariants checklist, and this item all describe that join. No `sync.Once` remains.

2. **major: extra test 10 hard-codes wrong expected counts.** Fixed, option (a). The 7-Get walk is in the test comment, MRU-first: after Get(`a`,`b`,`c`,`a`,`d`,`c`,`e`) the resident set is `{c, d, e}` with tail `d`, and `a` and `b` have been evicted. Counts at that point are all 1. The test then probes only residents, LRU-first (`d`, `c`, `e`), so each is a hit and nothing is evicted. It then probes `a` and `b`. It does not Get `c`, `d`, or `e` again: those Gets would miss and the counts would all become 2, which is the wrong assertion the finding rejected. Final assertion: `a=2`, `b=2`, `c=1`, `d=1`, `e=1`, `Len()==3`. The stream-of-consciousness wording is gone. The test is setup, action, assertion.

3. **minor: extra test 9's final probes are in an order that fails a correct cache.** Fixed. After `b` is admitted, resident is `{b}`. The test probes `b` first (hit, count stays 1), then `a` (reload, count becomes 2). The plan states why the reverse order fails: probing `a` first admits `a` and evicts `b`, so the following Get of `b` reloads. Each key has one release channel, created before any Get and closed once. `a`'s channel is already closed when `a` is reloaded, so that receive returns immediately and the reload does not block. The Loader does not allocate a new gate per call.

4. **minor: the success-path clone has two allowed placements.** Fixed. One placement, stated in the publish steps: if the Loader error is nil, `owned := clone(data)` runs before `mu` is taken. The closed re-check is under `mu` after that clone. If the cache closed during the clone, `owned` is dropped and the closed branch runs. The error path does not clone. There is no "or clone under `mu`" alternative.

5. **nit: publish ordering is stated two ways.** Fixed. One order, in the publish steps and the code sketch: under `mu`, delete the flight, set `result` / `err` / `finished`, `close(done)`, unlock. The sentence that said "publish fields, delete flight, set finished" is removed. Other sections name the branch; they do not restate a different order.

6. **nit: `clone`'s nil check is redundant.** Fixed. `clone` is `return bytes.Clone(b)`. The comment documents the contract: `bytes.Clone(nil)` is nil, and `bytes.Clone` of an empty non-nil slice is empty and non-nil. The wrapper stays as the single named copy point. No extra nil check.

7. **nit: `decide` panics on a non-conforming context and the panic can be mistaken for a cache bug.** Fixed. The comment and the panic string name the cause: `Done` is closed and `Err()` is nil, which breaks the context contract. With the three wake sources and the publication invariants, that caller bug is the only way `wait` reaches the branch. The branch still panics rather than returning `nil, nil`. The unit test still expects the panic when those flags are passed directly.

8. **nit: the plan said "match the spec verbatim" while adding a deadlock note to `Close`.** Fixed. The public API section says the exported declarations match the spec, and that the only difference is documentation: `Close`'s doc comment adds the deadlock sentences. Those sentences do not change the signature or the required behavior.

Additional correction, not in the findings: extra test 8 asserted `b` loaded once after Get(`a`), Get(`b`), Get(`a`), Get(`b`) at capacity 1. Step 3 evicts `b` and step 4 reloads it, so a correct cache has `a=2`, `b=2`, `Len()==1`. The test comment now has that walk, and the assertion matches it.
