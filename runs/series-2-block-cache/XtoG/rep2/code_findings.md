major: Get's locked recheck returns ctx.Err() whenever the caller context is done and f.done is not yet closed, without re-reading c.closed. Rule 7's priority while a load is in flight is (a) ErrClosed if the cache closes, else (b) ctx.Err(). A waiter whose context is already canceled, parked in the select at blockcache.go:97-101, wakes on ctx.Done(), takes the lock after Close has set closed and closed closeCh, and returns context.Canceled because the closed flag is checked only on entry to the recheck (lines 104-107) and is not checked again before the ctx.Err() return (lines 115-118). Reproduced 100/100 with -race: cancel the waiter, let it block in select, then Close while the loader is still blocked; the waiter returns context.Canceled while Close is still joining. Rule 8 also says Close wakes every current waiter with ErrClosed.
minor: runLoad recovers a panicking Loader and publishes fmt.Errorf("blockcache: loader panic: %v", p) to every waiter (blockcache.go:128-137). The spec does not define panic recovery. A panic becomes an ordinary flight error, the stack is discarded, and a later Get reloads. That keeps Close from deadlocking, but it changes the Loader contract. Document it on Loader, or fail the flight and re-panic after WaitGroup.Done and close(f.done) so the process still crashes.
nit: Get(nil, key) panics inside the wait select (blockcache.go:100) only on a miss that reaches the wait. A nil context on a resident hit returns the copy and never panics (lines 81-86). The two paths disagree, and a miss can start a Loader before the panic.
