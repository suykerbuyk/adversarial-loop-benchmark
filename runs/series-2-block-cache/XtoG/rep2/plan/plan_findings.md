minor: The data model lists only closeDone, closed after the loader join, but Close also closes a waiter notification channel before that join. Those have to be different channels. If an implementor uses closeDone for both and closes it to wake Gets, a second Close waiting on it returns before the join, which breaks rule 8 (a second Close during the join waits for that same join). Name the waiter channel in the data model and state that only the first Close closes each channel, once.
nit: Every returned slice needs one nil-preserving clone, including hit returns and coalesced flight-result returns, not only the bytes stored at admission. nil must stay nil, and a non-nil empty success must stay non-nil empty: append([]byte(nil), src...) turns a non-nil empty slice into nil. bytes.Clone does both. On a loader error, publish a nil slice with the error so waiters cannot observe the discarded bytes (rule 3).
nit: Evicting the front entry has to delete the resident map key and list.Remove that element in the same critical section as the insert. Removing only the list element leaves a hit for an evicted key and lets Len exceed capacity (rules 5 and 6). Admission-or-discard, flight-result publication, and exact-flight deletion belong in that same lock hold, before close(done) and before WaitGroup.Done, so a Get cannot observe neither a flight nor a resident and start a second Loader (rule 2).
