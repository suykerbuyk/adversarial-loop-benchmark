minor: Get's post-wake select treats a closed flight as authoritative even when the caller's context is also Done. Rule 7's priority is ErrClosed, then ctx.Err() if the caller context became Done while the load was still in flight, then the load result. Close of f.done and publication of f.value/f.err happen in the same critical section, and the outer select can wake from either channel. When both are ready, a canceled waiter that takes the f.done case is handed the payload (or the loader error) even though its context was already canceled before it observed completion. A context canceled before the loader returns, with the completion racing the recheck, therefore violates (b) over (c). Record completion before closing done, and after wake return ctx.Err() when the caller context is Done and that flag is still false.
minor: loadKey admits a successful result with an unconditional items[key] = el after an optional LRU eviction. It never looks up an existing resident for that key, and it deletes the flight only after the insert. Those two steps share one lock today, so a second flight of the same key cannot be published in between. Any later split of that critical section, or a Close path that removes the flight before the loader publishes, lets a second load insert a second list node for the same key and orphan the previous element. Len and eviction then disagree with the map. Under the publish lock, replace or skip when the key is already resident, and remove the matching flight only after that admission decision.
nit: The branch at Get's second select default returns ctx.Err() when the flight is not done and the caller context is not done. That path is unreachable if the outer select only returns after one of those channels closes, but the comment admits the race it is papering over and the return value is a nil error. A waiter that lands there is told the load succeeded with nil bytes. If the outer select is ever changed, this becomes a silent wrong result. Return only after rechecking closed, caller cancellation, and flight completion, and treat a still-pending flight as still in flight.
nit: A loader panic skips f.done close, flight-map removal, and loaders.Done. Every waiter of that key blocks until its own context ends, later Gets of the key join the abandoned flight, and Close blocks forever in loaders.Wait. The Loader type does not promise not to panic, and the goroutine is started by the cache. Recover in loadKey, publish the panic as an error, and always Done the WaitGroup.
nit: The package comment on Cache, Get, Len, and Close is thinner than the spec contract those methods implement. Rule 7's return priority, the cache-scoped loader context, and the "error wins over bytes" rule are not visible at the API. A later editor can "simplify" the post-wake select or the admission path without a local statement of the invariant.
