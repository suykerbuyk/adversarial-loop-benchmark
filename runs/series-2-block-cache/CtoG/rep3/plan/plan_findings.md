minor: tests 8b and 8e call `testHookWait` from the waiter goroutine and then block that same goroutine on `<-cl.done`, while `run` must finish and close `cl.done` for the hook to return. In a synctest bubble that is a deadlock: the waiter is blocked on a bubble channel, but `run` is blocked in the hook on a non-durable receive of `cl.done`, so `synctest.Wait` never returns and the bubble panics. Outside a bubble the same shape still hangs if the hook is the only thing that can unblock the Loader. Split the seam so the hook only signals an external driver, and let the test goroutine (or a goroutine that is not the waiter and not `run`) close `release`, call `Close`, and wait for `cl.done`. The waiter must not be the goroutine that joins the load.
nit: `testHookWait` is a production field whose only safe use is "set once before any Get, never written again." A later editor who sets it after `run` has started, or who has the hook call `Get` or `Len`, races the nil check or deadlocks on `mu` (`run` holds `mu` only after the Loader returns, but `Close` from the hook while `run` is still inside `load` is the one path test 8e relies on). Keep the hook out of the cache struct: a package-level test variable, or a `testing` build tag, so production `wait` has no seam and the lifetime rule is enforced by the compiler.
nit: `wait` documents that the final `ctx.Err()` is non-nil because the first select must have taken `ctx.Done()`. That is true only if every caller enters through `Get` after the already-Done check. `wait` itself is reachable with a live ctx if a test calls it directly, or if a future caller forgets that check, and then the last line returns `(nil, nil)`. Guard the last line with `if err := ctx.Err(); err != nil` and treat a live ctx as "keep waiting" (loop the select) so a missed Done cannot be published as success.
