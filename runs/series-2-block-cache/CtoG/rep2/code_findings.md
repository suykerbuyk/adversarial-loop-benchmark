Re-derived from spec rules 1–9 and the current wait/Close/runLoad paths: after a ctx or closing wake, wait decides under mu in order resolved, then closed, then ctx.Err(), and runLoad closes cl.done under that same mu, so a current waiter cannot observe ctx.Err() once Close has set closed. go test -race ./... passes; the public file matches instrument/resolve_public_test.go.
nit: afterWake sits on the production cache and is invoked on the wait path with no synchronization; it is nil in production, but a later edit that sets it from another goroutine, or that forgets it is test-only, races with wait.
nit: a Loader that calls Get for the same key deadlocks that load (and therefore Close, which joins it); other-key reentry works, and the spec does not require reentry, but nothing on Loader documents the same-key hang.
nit: a Loader that returns ErrClosed while the cache is still open is published unchanged, so callers cannot tell that Get from a real Close; rule 3 requires publishing the Loader error, so this is a contract footgun rather than a miss.
