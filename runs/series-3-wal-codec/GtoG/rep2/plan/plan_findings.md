minor: Passing the inner walker a two-index sub-slice does not keep it out of the next frame. In Go, `payload[4:]` still has cap running through the parent CRC and any sibling, so a later `cap`-based read or `append` can see or overwrite those bytes. That is the failure the amendment forbids ("never a read into the next outer frame"). The plan's len checks are safe only while every edit keeps using len. Clip each inner slice with a three-index expression (`payload[4:len(payload):len(payload)]`, and the same for each frame body) and add a local test the public suite does not cover: a depth-2 inner `len` that overruns its Batch but would form a valid frame if the parent bytes were visible, with a well-formed sibling after the outer Batch, must be `ErrCorrupt` and must not return that sibling as an inner record.
nit: The encode size rule contradicts itself. It says the Batch body is rejected with `errTooLarge` before allocation, and also that inner frames are encoded into a temporary buffer first. A literal reading allocates every inner frame, then checks the sum. Check the running uint64 body size after each inner encode and do not retain a frame once `1+4+sum` would pass 16 MiB, so the temporary buffer cannot grow past the cap.
nit: "A Batch whose own frame is at depth 8 is itself a legal record" is easy to implement as a successful return. The table and the walker are the parts that match the amendment and `TestBatchNestedPastDepth8`: a frame at depth 8 is the 9th wrap, its sub-stream would be depth 9, and Decode must return `(nil, ErrCorrupt)` even when `n = 0`, not a Batch value. Say that next to the walker so the prose cannot be implemented as success. Use one named depth constant on both the encode and decode paths so the two checks cannot drift and break "the encoder will not emit a stream it would itself reject."
nit: A cyclic `*Batch` (a record whose `Records` contains itself, directly or through another `*Batch`) is not in the edge-case list. The depth check stops it only if it runs before the recursive encode or decode call. Add that to the local checks; a later fast path that recurses before the check, or skips it for a pointer it has already seen, loops until the stack overflows instead of returning an error and a nil slice.
nit: Walker step 7 calls `decodeFrames` on the bytes after `n` but does not say the version (`limitTypes`) is passed through unchanged. Nested frames must use the outer stream's type rules: version 2 allows kinds 1, 2, and 3; a version-1 stream never parses a Batch payload. Also pin that Decode returns `Put`, `Delete`, and `Batch` values, not pointers — `recEq2` type-switches on the value types, so a `*Batch` fails every v2 round-trip.
