major: Decode error returns are still the v1 snapshot shape, which hands back already-parsed records. snapshot-v1/walcodec.go returns (records, corruptAt(off)) on a short header, oversize len, truncated body, bad CRC, or unknown kind, and the plan says only that those cases "return errors matching ErrCorrupt" while "port[ing] the existing v1 wire behavior". A caller that ignores the error then applies a prefix of a corrupt stream. The amendment keeps every v1 rule, and v1 requires a truncated, bad-CRC, unknown-type, or oversize frame to be ErrCorrupt; a successful prefix is not a successful decode. Pin both directions: every Decode failure, including a failure inside a nested Batch, returns (nil, err) with errors.Is(err, ErrCorrupt), and never a partial []Record.
major: Encode still accepts *Put and *Delete, which v2 Decode cannot round-trip. The snapshot type-switches on Put, *Put, Delete, and *Delete and encodes the pointer cases as kinds 1 and 2. The plan says "Accept only concrete value records Put, Delete, and Batch; reject nil interfaces, pointers (including nil pointers), and other implementations with ErrType", then says to port that snapshot. Those two sentences disagree. Decode is specified to append concrete values, never pointers, so Encode([]*Put{...}) would succeed and Decode would return []Record{Put{...}}, failing the v1 rule that Decode round-trips Encode output exactly. Reject every pointer and every non-value implementation with (nil, ErrType) before writing any frame; do not port the snapshot's pointer cases.
minor: Encode has no count or byte budget before it appends, so a legal-looking nest can allocate without bound. The plan caps each frame at 16 MiB, checks uint32 overflow, and returns (nil, err) on failure, but it still builds the full stream by recursive append, the way the snapshot does. Nine levels are forbidden, yet eight levels of Batch whose inner frames are each just under 16 MiB are legal on the wire and require on the order of 8*(16<<20) bytes of intermediate buffers before the outer frame is rejected as over cap. A hostile or accidental []Record tree can also be far larger than any frame cap, and the cap is discovered only after the children have been fully encoded. Preflight the encoded size (or encode into a budgeted buffer and discard it) so an over-cap Batch fails with ErrType before retaining child output, and apply the same budget at every depth.
nit: Version-1 kind gating is stated, but the plan does not say the gate is the same one used for unknown types after CRC. A v1 stream whose frame is kind 3 must be ErrCorrupt even when the Batch payload is well formed. Fold "kind not allowed for this version" into the post-CRC kind switch so it cannot be implemented as a separate pre-CRC walk.
