minor: The plan's extension story is inconsistent and will break the rule "the encoder ... will not emit a stream it would itself reject" the first time it is used. The plan says "Re-pointing `encodeTable` later is the extension." Today `measure` resolves nested `Batch` children through `codecOf`, which reads `encodeTable`. But `decodeBatch` hard-codes `&decodeV2Table` for inner frames, and the plan forbids a table parameter on `decode`/`bodyLen` (line 135). Suppose a v3 re-points `encodeTable` to add kind 4. `Encode` would then accept kind 4 inside a `Batch` and write it. `Decode` would reject that same `Batch` interior because it hard-codes the v2 grammar, so a v3 stream with a nested kind 4 does not round-trip. Version-1 streams cannot contain a `Batch`, so this does not affect them. The prior finding's suggested fix (the `Batch` decoder takes the inner table from its caller) was turned down in favor of a hard-coded global, so this half of that finding is still open. Fix: either let the version's table flow through `readFrame` into `decodeBatch` (for example `decode func(payload []byte, depth int, t *codecTable)`), with a matching table on the encode side, or remove the "re-point encodeTable" sentence and state that adding a kind means adding a new version with its own encode and decode tables, which `Batch` measure/decode must also be given.
nit: The pinned `init` snippet does not compile as written. Line 212 says `putCodec`, `deleteCodec`, and `batchCodec` are "`var` values of type `kindCodec`". But `byKind` is `[]*kindCodec`, so `kindPut: putCodec` is a type error. Write `&putCodec` (and the same for the other two), or declare the three as `*kindCodec`. I checked with go1.27.2: package-level literals `var batchCodec = kindCodec{..., decode: decodeBatch}` are acyclic as long as the three table vars have no initializer. So the "or as literals" option the plan allows is valid; only the address-of is missing.
nit: The Decode control-flow pseudocode (lines 272-274) reads as `if v==1 …; if v==2 …; else → ErrCorrupt`. Read literally, that rejects version 1. Write it as a `switch` with `case versionV1`, `case versionV2`, and `default: return nil, ErrCorrupt`, so nobody copies the sequential `if` into code.
nit: The plan gives two sources for the encode codec lookup. Line 216 says "`codecOf` type-switches, then `measure` looks up `encodeTable`". Line 306 says `codecOf` does the "Lookup … `encodeTable` only". The v1 `codecOf` already returns the `*kindCodec`. Say that `codecOf` returns `(*kindCodec, kind, error)` from `encodeTable` and that `measure` uses that result. Otherwise it is unclear which function does the table lookup, and the bounds check may get duplicated or dropped.
nit: The hostile-`n` internal test only asserts `ErrCorrupt`. The real risk is an allocation sized from `n`, and the test cannot catch that if the allocation is small enough not to crash (for example `make([]Record, 0, min(n, 1<<20))`). The test is in `package walcodec_test`, but `testing.AllocsPerRun` works through the exported API. Also assert a small, fixed allocation count (or bytes allocated) for decoding the ~20-byte `n=0xFFFFFFFF` frame, so the "no allocation from raw n" rule is checked directly.
