# Code findings — walcodec v2 (phase 2, code round 1)

Verification I ran myself (go1.27.2): `go build`, `go vet` clean; `go test -race` passes on amd64; `GOARCH=386 go vet` and `go test` pass; all 32 tests pass (9 v1 public, 8 v2 public, 15 implementor black-box); coverage 90.6%. The shipped v2 public test file is byte-identical to instrument/. The v1 public file is unchanged. I re-derived the code from source. Spec conformance holds. Encode writes version 2. Decode accepts versions 1 and 2 and rejects 0, 3, and an empty input before reading any frame. The version-1 table has no kind-3 slot, so a Batch in a version-1 stream is ErrCorrupt. Inner frames are read from the enclosing sub-slice, so an inner len that runs past its Batch is ErrCorrupt (truncated) and never reaches a sibling. The n frames must consume the payload exactly. The depth convention is: top level is depth 0; 8 wraps encode and decode; a 9th wrap, including an empty Batch, is rejected by both Encode and Decode. Every frame at every depth uses the same 16 MiB cap. My boundary probe confirmed that a Batch whose type+payload is exactly 16777216 bytes encodes and decodes, and that one byte more fails Encode with a non-ErrCorrupt error. A hostile n = 0xFFFFFFFF made 0 allocations (testing.AllocsPerRun). Decoded keys and values do not alias the input. A self-referencing Batch cycle is stopped by the depth cap. Nil, pointer (*Put, *Batch, nil *Put), and foreign Records fail Encode at every depth with a nil buffer. A 60 s fuzz run (24M executions) checked three properties: Decode never panics, it fails only with ErrCorrupt and nil records, and every accepted v2 stream re-encodes byte-identically. No failures. No shared mutable state after init and no goroutines, so there are no races.

minor: walcodec.go is not gofmt-clean (`gofmt -l .` lists it). The `versionV1 … kindBatch` const block (lines 61-65) is misaligned. The deliverable asks for idiomatic Go, and a gofmt CI gate would fail. Fix: run `gofmt -w walcodec.go`.
minor: Inner-frame CRC validation is untested in isolation. TestIntV2_InnerCRCFlip flips b[len-5] (the last inner CRC byte). The outer Batch CRC covers that byte, so the outer check rejects the stream first. Mutation proof: changing readFrame to check CRC only at depth 0 (`if depth == 0 && crc32.ChecksumIEEE(body) != gotCRC`) passes the whole suite. Fix: build a Batch whose inner frame has a bad CRC but whose outer CRC is recomputed to be valid. I wrote this probe; the current code returns ErrCorrupt.
minor: The encoder's 16 MiB cap is untested on both paths. Replacing `if body > maxFrameLen` in batchBodyLen with `if false` passes the suite, and the encoder would then emit an oversize Batch frame that its own Decode rejects. That breaks the amendment rule "the encoder ... will not emit a stream it would itself reject". The same is true of sizedBody's cap for top-level Put/Delete. Fix: add the boundary tests I wrote as a probe: a Batch whose body is exactly 16 MiB encodes and decodes, and one byte more fails Encode with a non-ErrCorrupt error and a nil buffer; the same for a top-level Put.
minor: The zero-len frame guard (`n < 1` in readFrame) is untested. Removing it passes the suite. Without it, `body[0]` on an empty body is an index-out-of-range panic, and a decoder must not panic on untrusted input. Fix: add a test with an inner and a top-level frame `len = 0` (+ 4 CRC bytes) that asserts ErrCorrupt.
minor: The extension comments are misleading. Lines 134 and 168 ("encodeTable is the encoder kinds. A later version re-points this."; "A future version re-points encodeTable only.") describe a step that cannot work alone. codecOf's hard-coded type switch would still reject a new kind. If the switch were extended too, Encode would still write `versionV2` (line 209) with kind 4 frames that decodeV2Table and decodeBatch's hard-coded `&decodeV2Table` reject, again breaking "encoder will not emit a stream it would itself reject". This was raised at plan stage and is still in the code. Fix: say that a new kind means a new version constant, a new decode table that is also passed to nested Batch decode, a codecOf case, and a new version byte in Encode. Or pass the active table through bodyLen/decode so nested Batch follows its stream's version.
nit: Dispatch is done three times for every record. codecOf type-switches the concrete type, then bounds-checks and indexes encodeTable, which is unreachable because the switch already limits kinds to 1-3. Then each bodyLen repeats the type assertion and returns a "unknown record type" error that cannot happen. Collapse this to a single dispatch so adding a kind touches fewer places.
nit: The hostile-n precheck (`uint64(n) > rest/minFrameWire` in decodeBatch) is not verified by any test. Removing it passes the suite, because append-only decode already bounds memory. TestIntV2_HostileN asserts only ErrCorrupt. Add a `testing.AllocsPerRun` bound (I measured 0 allocations) so a later regression that preallocates from n is caught.
nit: walcodec_v2_internal_test.go is `package walcodec_test`, which is a black-box external test, so the "internal" filename is wrong. Rename it, for example to walcodec_v2_extra_test.go.
nit: The comment block in TestIntV2_InnerLenCoversSibling is about 70 lines of design notes, including restarted reasoning ("Simpler construction from the plan", "That's circular if ..."), for about 15 lines of code. Cut it to a short layout diagram of the forged stream.
nit: readRecords has two near-duplicate loops (limit < 0 and limit >= 0), each with its own `recs == nil` normalisation. One loop with `for (limit < 0 && len(rest) > 0) || (limit >= 0 && i < limit)` plus one trailing check would remove the duplication.
nit: Encode errors are anonymous fmt.Errorf values. The doc tells callers to detect encode failure by `!errors.Is(err, ErrCorrupt)` and not to match strings, so callers cannot tell a depth error from a cap error or a bad-type error. This is allowed by the frozen surface (no new exported symbols except Batch), so it is noted only. If the surface opens later, add unexported-wrapped sentinels.

No blocker or major issue remains.
