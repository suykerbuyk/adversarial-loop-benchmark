minor: The plan never says that decoded Put values are copied out of the input buffer at every depth. v1 `decodeBody` does `make`+`copy`, so returned records never alias `b`. The plan's "What stays" lists the grammar, the nil/empty equivalence and the error contract, but not this no-aliasing rule. It also plans a rewrite into a slice-bounded recursive parser that works on sub-slices of the input, which is exactly where a sub-slice Value could creep in, and no public or private test would catch it. Fix: state that every decoded `Value` (top-level and inside any Batch) is a fresh copy, keep it in the Decode doc comment, and add a private test that mutates the input after Decode and checks that a nested Put's Value is unchanged.
minor: The plan states the 8-deep cap and the 13-byte minimum frame as literals and does not tie them to named constants that Encode and Decode share. The amendment requires the encoder and decoder to use the identical cap ("the encoder ... will not emit a stream it would itself reject"). Two hand-written depth comparisons (`> 8` versus `>= 9`, depth checked before or after the increment) are the most likely long-term drift point, and the `/13` count bound will silently reject valid streams if a smaller record type or payload is ever added. Fix: define a single `maxBatchDepth = 8` and one helper for entering a child depth that both paths call. Derive the minimum frame size from named pieces (len 4 + type 1 + min payload 4 + crc 4) with a comment saying why 4 is the smallest payload (an empty-key Delete or an empty Batch).
nit: "exact/beyond frame-size boundaries" does not name the Batch-specific boundary. Pin a Batch whose body is exactly 16 MiB built from children that are each under the cap: it must Encode and Decode. Pin the same Batch plus one byte: Encode must fail, not ErrCorrupt by identity, with nil bytes. Also pin a leaf Put at the leaf cap (16 MiB - 9 value bytes) wrapped in one Batch: it must fail Encode because the wrapper adds 13 bytes. These cases exercise the new running-body early abort and the final authoritative check.
nit: The fuzz property only checks that `Encode(Decode(b))` succeeds and then decodes again. The v2 wire format is canonical (exact counts, exact lengths, no padding), so for any accepted input with version byte 2, `Encode(Decode(b))` must equal `b` byte for byte. Asserting byte identity would catch encode/decode asymmetries (count placement, length off-by-one, depth or version policy drift) that a decode-again check misses.
nit: Say in the Batch doc comment (and pin in a test) that `Batch{Records: nil}` and `Batch{Records: []Record{}}` encode identically (count 0) and both decode to a non-nil empty slice. This mirrors the v1 nil/empty `Value` rule. A future caller comparing with `reflect.DeepEqual` would otherwise be surprised.
nit: "the internal errBatchTooDeep may remain distinguishable" is non-committal. An unexported sentinel cannot be matched by callers anyway. Either drop it and return a plain `fmt.Errorf("%w: batch nesting exceeds depth 8", ErrCorrupt)`, or commit to it and use it in the private test. Do not leave the choice to the implementor. Multi-`%w` is fine under go 1.25 in go.mod.
nit: Acceptance runs only the fuzz seed corpus (`go test`). Add a short bounded fuzz smoke run (e.g. `go test -run='^$' -fuzz=FuzzDecode -fuzztime=30s`) so the new recursive Batch parser gets at least some mutation coverage before convergence.
