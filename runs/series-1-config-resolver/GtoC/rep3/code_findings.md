minor: Unknown keys still panic (resolve.go, layer.apply). The spec only requires a panic for a wrong-typed value. The rebuttal kept this on purpose, and it is now documented on Resolve ("Unknown keys are not ignored") and written into the hand-off note. I accept the rationale: dropping a typo silently would let a lower layer show through. The risk remains: an external caller or acceptance test that passes an extra key gets a crash, where a literal reading of the spec would allow ignoring it. No code change required. It stays here so the stricter-than-spec contract is visible.
nit: The Resolve doc comment hard-codes the four key names and their types ("bool, int, string, int respectively"). This is the one per-field fact that sits outside the fields table and that no test checks, so it will drift as fields are added (the spec says fields will be added). Consider a shorter wording ("the keys are the exported Config field names; each value must have exactly the field's type") that stays true as fields grow.
nit: knownKeys (map[string]struct{}) and fields ([]field) hold the same key set twice, and layer.apply makes two passes: one over the layer to find unknown keys, one over fields with a map lookup each. A single map[string]field index would let one loop over the layer both detect unknown keys and apply known ones. The unknown-before-any-apply ordering could be kept by collecting first. Small and not a correctness issue.
nit: `if l.values == nil { return }` in layer.apply is redundant. Ranging over and indexing a nil map is legal and does nothing, as the surviving equivalent mutation confirms. It is harmless but adds a branch that looks meaningful.
nit: The comment in TestUnknownKeyListCapped says "Multibyte runes sort after ASCII", but every key in that test is multibyte. Truncation shows only because 世 (U+4E16) sorts below the other CJK keys (U+5440..U+55EF). The comment explains the wrong invariant, so a maintainer who swaps characters could silently lose the truncation check. The test would then fail loudly rather than pass wrongly, so the impact is low.

Summary: no blocker or major issue remains. The round-1 major (file/env precedence not pinned) is fixed and confirmed by mutation. What remains is one deliberate stricter-contract minor and four nits.
